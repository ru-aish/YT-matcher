# Dark-themed landing page with animated sections for YT Matcher

This change replaces the placeholder landing page with a fully styled, animated marketing site. Five client-side React components (Hero, HowItWorks, InteractiveDemo, SocialProof, CTA) deliver a dark-themed landing page built on Tailwind CSS v4, framer-motion for scroll and interaction animations, and Google Fonts (Space Grotesk + Outfit) loaded via Next.js's font system. The design system lives in CSS custom properties in `globals.css`, with custom utility animations for floating elements and marquee scrolling. The page is entirely presentational with hardcoded demo data and no backend integration.

**Watch for:** All five section components are marked `'use client'`, meaning the entire page ships as client-side JavaScript with zero static HTML content (confirmed). The InteractiveDemo has no way to undo a match action once triggered (confirmed). The `AnimatedCounter` in SocialProof uses raw `requestAnimationFrame` without cleanup on unmount (confirmed).

## High-level view

Every section component is a client component, which means Next.js cannot statically render any page content. For a marketing landing page where SEO and initial paint speed are primary concerns, this is a significant architectural trade-off: the browser must download, parse, and execute framer-motion and all component code before any content appears.

The InteractiveDemo introduces the only interactive state on the page: a filter + match mechanism using local `useState`. The match action is one-way (cards disappear permanently until page reload), which will confuse users expecting a toggle or reset.

The SocialProof section's `AnimatedCounter` drives `requestAnimationFrame` loops that are not cancelled if the component unmounts mid-animation, creating a state-update-on-unmounted-component issue.

No `prefers-reduced-motion` handling exists anywhere in the CSS or components. The page has continuous infinite animations (floating shapes, spinning ring, marquee) that run regardless of user motion sensitivity settings.

## Client-only rendering for a marketing page

Every component file begins with `'use client'`. In Next.js App Router, this means the entire page tree is excluded from static rendering. The page.js itself imports these five components directly, so even though page.js doesn't have the directive, the entire render tree is client-side.

For a landing page whose primary job is SEO visibility and fast first-contentful-paint, this is an expensive choice. The Hero headline ("Where Creators Meet Brands"), the HowItWorks steps, the testimonials, and the CTA copy are all static text that could render as server HTML. Framer-motion supports a pattern where the `motion` wrapper is isolated in a small client component while the surrounding content remains server-rendered.

The practical impact: search engines will see an empty `<main>` until JavaScript executes, and users on slow connections will see a blank dark screen until ~200KB+ of JavaScript (React + framer-motion + component code) loads and hydrates.

## AnimatedCounter resource leak

In `SocialProof.js`, the `AnimatedCounter` component starts a `requestAnimationFrame` loop inside `useEffect`:

```javascript
useEffect(() => {
  if (!isInView) return
  // ...
  function animate(currentTime) {
    // ...
    if (progress < 1) {
      requestAnimationFrame(animate)
    }
  }
  requestAnimationFrame(animate)
}, [isInView, target])
```

There is no cleanup function returned from this effect. If the component unmounts while the animation is running (during navigation or hot-reload), the RAF callback will attempt to call `setCount` on an unmounted component. Store the RAF ID and return a cleanup that calls `cancelAnimationFrame`.

## One-way match interaction

The InteractiveDemo's `handleMatch` appends IDs to `matchedIds` and filters matched cards out of the rendered list. Once all six creators are matched, the grid is empty with only the "6 creators matched!" indicator visible. There is no unmatch button, no reset affordance, and no way to restore the demo state without reloading. A "Reset" button or a matched-creators tray with unmatch capability would make this behave like an actual product preview rather than a one-shot animation.

## Missing prefers-reduced-motion

There is no `prefers-reduced-motion` media query in `globals.css` and no use of framer-motion's `useReducedMotion` hook or `reducedMotion` prop in any component. The page runs continuous animations: three floating gradient blobs, six floating geometric shapes, a spinning dashed ring, and an infinite brand marquee. All of these violate WCAG 2.1 SC 2.3.3 (Animation from Interactions) for users with vestibular disorders. At minimum, the CSS keyframe animations should be paused under `@media (prefers-reduced-motion: reduce)` and framer-motion should be configured with `reducedMotion="user"` at the `LazyMotion` or `MotionConfig` level.

## Hardcoded data as social proof

The stats in SocialProof ("10,000+ Creators", "$5M+ Deals Closed", "98% Match Rate") and the CTA footer ("Join 12,500+ creators and brands already matched") present specific numbers as factual. If this is a pre-launch product, these claims could be problematic from a trust/legal perspective. The brand marquee uses clearly fictional company names ("TechCorp", "GameHub"), which is fine as placeholder content, but the numeric claims read as factual assertions about platform traction that doesn't exist yet.
